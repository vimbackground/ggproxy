# ggproxy 手动部署操作手册

本文档说明如何手动把 ggproxy 部署到 Cloudflare、Vercel、Deno 和 Netlify。平台顺序固定为：Cloudflare → Vercel → Deno → Netlify。

## 1. 部署前准备

### 1.1 准备代码和账号

- GitHub 仓库：`https://github.com/vimbackground/ggproxy`
- 本地建议安装 Git 和 Node.js 18 或更高版本。
- 按目标平台准备 Cloudflare、Vercel、Deno 或 Netlify 账号。
- 如需从自己的仓库持续部署，先 Fork 本项目，后续连接 Fork 后的仓库。

### 1.2 选择密钥模式

ggproxy 支持两种 Gemini API Key 使用方式：

1. BYOK：调用方每次通过官方认证头传入 Gemini Key。
2. 服务端 Key 池：平台环境变量中配置 `GEMINI_API_KEYS`。

生产部署推荐同时配置独立的网关令牌：

```text
PROXY_TOKEN=请使用密码管理器生成的高强度随机值
```

配置后，每个业务请求还必须携带：

```http
x-proxy-token: 你的网关令牌
```

不要把 API Key、`PROXY_TOKEN` 或 `.env` 文件提交到 GitHub。

### 1.3 可用环境变量

| 变量 | 是否必需 | 默认值 | 用途 |
|---|---|---:|---|
| `PROXY_TOKEN` | 生产环境建议 | 空 | 限制谁可以使用代理 |
| `GEMINI_API_KEYS` | BYOK 模式不需要 | 空 | 服务端 Gemini Key 池，多个 Key 以英文逗号分隔 |
| `DEFAULT_GEMINI_MODEL` | 否 | `gemini-2.5-flash` | OpenAI/Claude 模型名的默认映射目标 |
| `MAX_BODY_BYTES` | 否 | `10485760` | 最大请求体字节数 |
| `UPSTREAM_TIMEOUT_MS` | 否 | `120000` | Gemini 上游超时毫秒数 |
| `CORS_ORIGINS` | 浏览器调用时需要 | 空 | 允许的 Origin，多个值以英文逗号分隔 |
| `VERIFY_ENABLED` | 否 | `false` | 是否启用 `/verify` Key 验证接口 |

敏感值应保存为平台的 Secret；只有模型名、超时、大小限制等非敏感配置才使用普通变量。

## 2. Cloudflare 手动部署

仓库已经包含 [wrangler.toml](../wrangler.toml)，Worker 名称为 `g2g`，入口为 `src/index.js`。

### 2.1 使用 Wrangler CLI 部署

在终端执行：

```bash
git clone https://github.com/vimbackground/ggproxy.git
cd ggproxy
npm install
npx wrangler login
npx wrangler deploy
```

部署成功后会得到类似以下地址：

```text
https://g2g.<你的子域>.workers.dev
```

### 2.2 配置 Secret

逐项执行并根据提示输入值：

```bash
npx wrangler secret put PROXY_TOKEN
npx wrangler secret put GEMINI_API_KEYS
```

也可以进入 Cloudflare Dashboard：

```text
Workers & Pages → g2g → Settings → Variables and Secrets → Add
```

选择 `Secret`，保存后部署新版本。Cloudflare 官方明确要求敏感信息使用 Secret，而不是写入 `wrangler.toml` 的普通变量。

### 2.3 可选：连接 GitHub 自动更新

进入：

```text
Workers & Pages → g2g → Settings → Builds → Connect
```

选择 GitHub 仓库和 `main` 分支，使用以下配置：

| 配置项 | 值 |
|---|---|
| Root directory | 仓库根目录或留空 |
| Build command | 留空 |
| Deploy command | `npx wrangler deploy` |
| Production branch | `main` |

Worker 名称必须与 `wrangler.toml` 中的 `name = "g2g"` 一致，否则 Git 构建会失败。

### 2.4 Cloudflare 验证

```bash
curl https://你的-workers-域名/healthz
```

期望返回：

```json
{"name":"ggproxy","status":"ok","protocols":["gemini","openai","anthropic"]}
```

## 3. Vercel 手动部署

仓库中的 [vercel.json](../vercel.json) 会把所有路径转给 `api/vercel_index.js`。

### 3.1 从 GitHub 导入

1. 登录 [Vercel Dashboard](https://vercel.com/dashboard)。
2. 选择 `Add New` → `Project`。
3. 连接 GitHub，导入 `vimbackground/ggproxy` 或你的 Fork。
4. Framework Preset 选择 `Other`。
5. Root Directory 保持仓库根目录。
6. 不填写 Build Command 和 Output Directory。
7. 在 Environment Variables 中添加 `PROXY_TOKEN`、`GEMINI_API_KEYS` 及其他需要的变量。
8. 敏感变量至少应用到 `Production`；如需预览分支，也选中 `Preview`。
9. 点击 `Deploy`。

Vercel 会读取 `vercel.json`，无需把 `/v1/chat/completions` 等接口路径改成 Vercel 专属路径。

### 3.2 使用 Vercel CLI 部署

```bash
npm install -g vercel
vercel login
vercel link
vercel env add PROXY_TOKEN production
vercel env add GEMINI_API_KEYS production
vercel deploy --prod
```

如果已经通过 Dashboard 配置变量，可以直接执行最后一条部署命令。

### 3.3 Vercel 验证

```bash
curl https://你的-vercel-域名/healthz
```

连接 GitHub 后，推送到生产分支会自动产生 Production Deployment；其他分支或 Pull Request 通常产生 Preview Deployment。

## 4. Deno 手动部署

> 注意：Deno Deploy Classic 已于 2026-07-20 停止服务。不要再使用旧的 `dash.deno.com` 或 `deployctl` 流程；新版入口是 [console.deno.com](https://console.deno.com)，命令行为 `deno deploy`。

仓库的动态入口是 `src/deno_index.ts`。

### 4.1 使用新版 Deno Deploy Dashboard

1. 登录 [Deno Deploy Console](https://console.deno.com)。
2. 创建或选择 Organization。
3. 点击 `+ New App`。
4. 选择 GitHub 仓库；如果仓库不可见，配置 Deno GitHub App 的仓库权限。
5. 打开 `Edit build config`，确认：

| 配置项 | 值 |
|---|---|
| Runtime mode | `Dynamic` |
| Entrypoint | `src/deno_index.ts` |
| Working directory | 仓库根目录 |
| Install command | 留空 |
| Build command | 留空 |

6. 点击 `Add/Edit environment variables`。
7. 将 `PROXY_TOKEN` 和 `GEMINI_API_KEYS` 设置为 Secret，并应用于 Production；按需同时应用于 Development。
8. 点击 `Create App`，等待构建完成。

### 4.2 使用 Deno CLI 创建应用

先安装当前版本 Deno，然后执行交互式命令：

```bash
deno deploy create
```

也可以显式指定 GitHub 来源：

```bash
deno deploy create \
  --source github \
  --owner vimbackground \
  --repo ggproxy \
  --runtime-mode dynamic \
  --entrypoint src/deno_index.ts
```

应用创建后，根据 CLI 提示或 Dashboard 配置 Secret。CLI 支持以下形式：

```bash
deno deploy env add PROXY_TOKEN "你的随机令牌" --secret
deno deploy env add GEMINI_API_KEYS "你的Gemini-Key" --secret
```

如果同一账号有多个 Organization 或 App，请按照 CLI 帮助补充 `--org` 和 `--app`。

### 4.3 Deno 验证

```bash
curl https://你的-deno-域名/healthz
```

GitHub 集成建立后，每次推送都会生成新的构建和 Revision。

## 5. Netlify 手动部署

仓库已经包含 [netlify.toml](../netlify.toml)，所有路径都会重写到 `netlify/functions/api.js`。Netlify 默认函数目录正是 `netlify/functions`。

### 5.1 从 GitHub 导入

1. 登录 [Netlify](https://app.netlify.com)。
2. 选择 `Add new project` → `Import an existing project`。
3. 选择 GitHub 并导入 `vimbackground/ggproxy` 或你的 Fork。
4. 使用以下构建设置：

| 配置项 | 值 |
|---|---|
| Base directory | 留空 |
| Build command | 留空 |
| Publish directory | 留空 |
| Functions directory | `netlify/functions` |

5. 在 `Project configuration` → `Environment variables` 中添加 `PROXY_TOKEN` 和 `GEMINI_API_KEYS`。
6. 点击 `Deploy`。

`netlify.toml` 中的文件配置优先于 Dashboard 中冲突的配置。如曾手动修改重写规则，应以仓库文件为准。

### 5.2 使用 Netlify CLI 部署

```bash
npm install -g netlify-cli
netlify login
netlify init
netlify env:set PROXY_TOKEN "你的随机令牌"
netlify env:set GEMINI_API_KEYS "你的Gemini-Key"
netlify deploy --prod
```

首次执行 `netlify init` 时，选择创建新站点或连接已有站点。

### 5.3 Netlify 验证

```bash
curl https://你的-netlify-域名/healthz
```

## 6. 部署后统一冒烟测试

以下示例假设已经配置 `PROXY_TOKEN` 和服务端 `GEMINI_API_KEYS`：

### 6.1 Gemini 原生格式

```bash
curl "https://你的域名/v1beta/models/gemini-2.5-flash:generateContent" \
  -H "x-proxy-token: 你的网关令牌" \
  -H "content-type: application/json" \
  -d '{"contents":[{"parts":[{"text":"reply only: ok"}]}]}'
```

### 6.2 OpenAI 格式

```bash
curl "https://你的域名/v1/chat/completions" \
  -H "x-proxy-token: 你的网关令牌" \
  -H "content-type: application/json" \
  -d '{"model":"gemini-2.5-flash","messages":[{"role":"user","content":"reply only: ok"}]}'
```

### 6.3 Claude 格式

```bash
curl "https://你的域名/v1/messages" \
  -H "x-proxy-token: 你的网关令牌" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{"model":"claude-compatible","max_tokens":32,"messages":[{"role":"user","content":"reply only: ok"}]}'
```

如果未配置服务端 `GEMINI_API_KEYS`，还需要按协议携带调用方 Gemini Key：Gemini 使用 `x-goog-api-key`，OpenAI 使用 `Authorization: Bearer ...`，Claude 使用 `x-api-key`。

## 7. 常见问题

### 返回 `missing_api_key`

请求没有携带上游 Key，且平台没有配置 `GEMINI_API_KEYS`。

### 返回 `invalid_proxy_token`

平台已经配置 `PROXY_TOKEN`，但请求没有携带相同的 `x-proxy-token`。

### 浏览器出现 CORS 错误

配置准确的 `CORS_ORIGINS`，例如：

```text
CORS_ORIGINS=https://chat.example.com,https://admin.example.com
```

除非代理本身已经有严格访问控制，否则不建议设置成 `*`。

### `/v1/models` 被识别为错误协议

- Gemini 请求携带 `x-goog-api-key`，或改用 `/gemini/v1/models`。
- OpenAI 请求携带 `Authorization: Bearer ...`，或改用 `/openai/v1/models`。

### 更新 Secret 后没有生效

确认变量应用于当前环境，并重新部署或触发一次 Production Build。
