# ggproxy 手动部署操作手册

ggproxy 的正式部署平台只有 Cloudflare Workers 和 Vercel Edge。部署完成后，按 [README](../README.md) 中的“先看地址和 Key”选择调用方式。

## 部署前准备

准备 GitHub 仓库、Node.js 22+，以及 Cloudflare 或 Vercel 账号。所有 Token、Gemini API Key 和 KV 写入令牌都只能填写在平台的环境变量或 Secret 中，不能提交到仓库。

如果只提供 BYOK 功能，不需要配置 Gemini API Key 或后台存储。若要通过后台向用户发放 `ggp_...` 令牌，则必须配置后台所需的全部项目。

| 配置项 | 何时需要 | 作用 |
|---|---|---|
| `ADMIN_TOKEN` | 使用后台时 | `/admin` 的登录口令 |
| `ADMIN_ENCRYPTION_KEY` | 在后台保存服务端 Key 时 | 至少 32 个字符；用于加密服务端 Gemini API Key |
| 管理存储 | 使用后台时 | 保存加密后的服务端 Key、策略和客户端令牌哈希 |
| `GEMINI_API_KEYS` | 可选 | 后台没有启用 Key 时的兼容回退；多个 Key 用英文逗号分隔 |
| `DEFAULT_GEMINI_MODEL` | 可选 | OpenAI/Claude 请求中非 Gemini 模型名的默认模型；默认 `gemini-3.5-flash-lite` |
| `CORS_ORIGINS` | 浏览器直接调用时 | 允许的网页来源，多个值用英文逗号分隔 |

## Cloudflare Workers

仓库已经包含 `wrangler.toml` 和入口文件 `src/index.js`。

```bash
git clone https://github.com/vimbackground/ggproxy.git
cd ggproxy
npm install
npx wrangler login
npx wrangler deploy
```

### 启用后台中转

1. 打开 **Settings → Runtime variables and secrets**，添加两个 Secret：`ADMIN_TOKEN` 和至少 32 个字符的 `ADMIN_ENCRYPTION_KEY`。
2. 保存配置并重新部署 Worker。
3. 打开 `https://你的域名/admin`，使用 `ADMIN_TOKEN` 登录。添加服务端 Gemini API Key、设置策略，然后创建客户端令牌。

仓库的 `wrangler.toml` 已声明 `GGPROXY_ADMIN_KV`。Cloudflare Git 自动部署会在首次部署时自动创建 KV 并绑定给 Worker，之后会持续使用同一个绑定；不需要每次在 Dashboard 手工添加 Binding。

**已存在的后台数据：**如果旧版本的手工 KV 绑定已经被部署删除，但还需要其中的 Key、令牌和策略，请先在 **Settings → Bindings** 将原来的 KV namespace 重新绑定为 `GGPROXY_ADMIN_KV`，再部署本版本。这样会保留原有数据。若直接部署且当前没有绑定，Cloudflare 会创建新的空 KV，旧 namespace 中的数据不会自动迁移。

KV 会保存加密后的服务端 Gemini API Key、模型策略和客户端令牌哈希。修改或删除 `ADMIN_ENCRYPTION_KEY` 后，之前保存的服务端 Key 将无法解密；不要更改它，除非准备重新录入全部服务端 Key。

## Vercel Edge

仓库中的 `vercel.json` 会将请求交给 Edge 入口 `api/vercel_index.js`。

1. 在 [Vercel Dashboard](https://vercel.com/new) 选择 **Add New → Project**，导入仓库。
2. Framework Preset 选择 `Other`；Root Directory 保持仓库根目录；Build Command 和 Output Directory 留空。
3. 如果只使用 BYOK，可直接点击 Deploy。
4. 如果使用后台中转，在 Environment Variables 中添加下方四项，再点击 Deploy。

```text
ADMIN_TOKEN=高强度随机值
ADMIN_ENCRYPTION_KEY=至少32个字符且已妥善备份的随机值
ADMIN_KV_REST_URL=https://你的-kv-rest-地址
ADMIN_KV_REST_TOKEN=有写入权限的令牌
```

管理存储必须兼容 Upstash REST API。也可使用 `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`，或 `KV_REST_API_URL` / `KV_REST_API_TOKEN`。这三组变量任选一组即可，地址和令牌必须成对设置。

## 部署后检查

先访问：

```text
https://你的域名/healthz
```

收到 `status: ok` 表示 Worker 已运行。若已配置后台，打开：

```text
https://你的域名/admin
```

创建 `ggp_...` 客户端令牌，并至少添加一个已启用的服务端 Gemini API Key 后，用 Gemini 原生地址测试：

```bash
curl https://你的域名/v1beta/models/gemini-3.5-flash-lite:generateContent \
  -H "x-goog-api-key: 后台创建的客户端令牌" \
  -H "content-type: application/json" \
  -d '{"contents":[{"parts":[{"text":"reply only: ok"}]}]}'
```

成功后，将中转域名和客户端令牌交给用户，并让用户按 [Kelivo 用户使用教程](Kelivo用户使用教程.md) 配置。用户自带 Key 时应改用带协议前缀的 BYOK 地址：`/openai/v1`、`/gemini/v1beta` 或 `/claude/v1`。

## 常见问题

### `/admin` 返回 404

当前运行环境没有 `ADMIN_TOKEN`。在 Cloudflare 必须添加到 **Runtime variables and secrets**，并在保存后重新部署；在 Vercel 必须添加到 Environment Variables 并产生新的部署。

### 后台提示需要管理存储

Cloudflare：确认当前运行的版本已包含仓库中 `wrangler.toml` 的 `GGPROXY_ADMIN_KV` 声明。首次部署后，在 **Settings → Bindings** 应能看到同名 KV Binding。Vercel：检查 REST KV 的地址与令牌是否成对设置。

### `ggp_...` 令牌返回 `invalid_proxy_token`

确认请求使用 Gemini 原生地址，例如 `/v1beta/models/...`，并将令牌放在 `x-goog-api-key` 或 `key` 查询参数。确认令牌没有被后台撤销，也没有多出空格。

### `ggp_...` 令牌返回 `no_upstream_key`

在后台添加至少一个服务端 Gemini API Key 并保持启用。若 Key 已保存但仍失败，确认 `ADMIN_ENCRYPTION_KEY` 与保存 Key 时完全相同。
