# ggproxy 自动化部署操作指南

本指南只覆盖正式支持的 Cloudflare Workers 与 Vercel Edge。连接已有 GitHub 仓库即可持续部署；不需要 Fork，也不再提供 Deno 或 Netlify 的自动化流程。

## Cloudflare Workers

1. 打开 [Workers & Pages](https://dash.cloudflare.com/?to=/:account/workers-and-pages)，选择 **Create application → Import a repository**。
2. 授权并选择当前 `ggproxy` 仓库和生产分支。
3. Worker 名称使用 `ggproxy`，部署命令保持 `npx wrangler deploy`。
4. 在 **Settings → Runtime variables and secrets** 添加 `ADMIN_TOKEN`、至少 32 位的 `ADMIN_ENCRYPTION_KEY`，并绑定 `GGPROXY_ADMIN_KV`；随后在后台添加 Gemini Key。
5. 保存并部署。以后推送到生产分支会自动发布。

如需后台令牌管理，再创建 KV namespace 并将它绑定为 `GGPROXY_ADMIN_KV`，同时添加 `ADMIN_TOKEN`。详情见[手动部署操作手册](手动部署操作手册.md)。

## Vercel Edge

1. 打开 [Vercel New Project](https://vercel.com/new)，导入当前 `ggproxy` 仓库。
2. Framework Preset 选择 `Other`，不填写 Build Command 和 Output Directory。
3. 在 Environment Variables 添加 `ADMIN_TOKEN`、至少 32 位的 `ADMIN_ENCRYPTION_KEY`，以及管理 KV 的 REST 地址和令牌；随后在后台添加 Gemini Key，点击 Deploy。
4. 以后生产分支提交会生成 Production Deployment；其他分支通常生成 Preview Deployment。

如需后台令牌管理，额外设置 `ADMIN_TOKEN`、`ADMIN_KV_REST_URL` 和 `ADMIN_KV_REST_TOKEN`（或兼容的 Upstash/Vercel KV 变量名）。

## 验证与发布后交付

访问：

```text
https://你的域名/healthz
```

若返回 `status: ok`，管理员可以打开：

```text
https://你的域名/admin
```

创建用户令牌后，将“中转网址”和“用户令牌”发给用户即可。用户不用接触部署、后台或 Gemini Key；可直接按 [Kelivo 用户使用教程](Kelivo用户使用教程.md) 配置。

## 回滚

- Cloudflare：在 Worker 的 Deployments / Versions 中选择已验证版本重新部署。
- Vercel：在 Deployments 中打开已验证部署并 Promote 或 Redeploy。

回滚部署不会自动恢复后来改动的环境变量或已撤销的用户令牌；二者需要分别处理。
