# ggproxy 自动化部署操作指南

本指南使用已有 GitHub 仓库的自动部署。正式支持 Cloudflare Workers 和 Vercel Edge；Deno 与 Netlify 没有独立部署流程。

## 先决定是否使用后台中转

- 只让调用者使用自己的 Gemini API Key：部署后即可使用 BYOK，不需要后台、KV 或服务端 Key。
- 需要发放 `ggp_...` 用户令牌：部署时必须配置后台登录、加密密钥和管理存储；随后在 `/admin` 添加服务端 Gemini API Key。

两种方式的 URL 和 Key 填写方法见 [README](../README.md)。

## Cloudflare Workers

1. 打开 [Workers & Pages](https://dash.cloudflare.com/?to=/:account/workers-and-pages)，选择 **Create application → Import a repository**。
2. 授权 GitHub 并选择 `ggproxy` 仓库和生产分支。
3. 部署命令使用 `npx wrangler deploy`。
4. 如果使用后台，在 **Settings → Bindings** 添加 KV Namespace Binding，变量名必须为 `GGPROXY_ADMIN_KV`。
5. 在 **Settings → Runtime variables and secrets** 添加 `ADMIN_TOKEN` 和至少 32 个字符的 `ADMIN_ENCRYPTION_KEY`。
6. 保存后触发一次新部署。之后向生产分支推送提交会自动发布。

不要把 `ADMIN_TOKEN` 误填在 Build Variables 或其他非运行时区域；后台运行时只能读取 **Runtime variables and secrets** 中的值。

## Vercel Edge

1. 打开 [Vercel New Project](https://vercel.com/new)，导入 `ggproxy` 仓库。
2. Framework Preset 选择 `Other`，Build Command 和 Output Directory 留空。
3. 如果使用后台，在 Environment Variables 中添加 `ADMIN_TOKEN`、`ADMIN_ENCRYPTION_KEY`、`ADMIN_KV_REST_URL` 和 `ADMIN_KV_REST_TOKEN`。
4. 点击 Deploy。以后生产分支提交会生成 Production Deployment，其他分支通常生成 Preview Deployment。

详细的 KV 和变量说明见 [手动部署操作手册](手动部署操作手册.md)。

## 验证和交付

1. 访问 `https://你的域名/healthz`，确认返回 `status: ok`。
2. 若使用后台，访问 `https://你的域名/admin`，登录后添加服务端 Key、设置策略并创建 `ggp_...` 令牌。
3. 将中转网址和 `ggp_...` 令牌交给用户。用户应选择 Gemini 原生供应商，不能将该令牌填入 OpenAI 或 Claude 供应商。

普通用户的完整配置步骤见 [Kelivo 用户使用教程](Kelivo用户使用教程.md)。

## 回滚

- Cloudflare：在 Worker 的 Deployments 或 Versions 中重新部署已验证版本。
- Vercel：打开已验证的 Deployment 后选择 Promote 或 Redeploy。

回滚代码不会恢复之后修改的环境变量、后台策略或已撤销的客户端令牌；它们需要分别重新配置。
